## Приоритеты при принятии решений

Строим **высоконагруженное**, **защищённое**, **качественное** приложение. Любое решение оценивается по трём критериям:

1. **Нагрузка** — выдержит ли при росте трафика? Нет N+1, тяжёлых запросов без лимитов, блокирующих операций.
2. **Безопасность** — нет ли уязвимостей? Валидация, авторизация, отсутствие утечек данных.
3. **Качество** — читаемый код, без дублирования, следование стандартам проекта.

Если решение ухудшает хотя бы один из трёх — ищем другой вариант.

## Принципы разработки

- Модульность: каждый модуль изолирован, не лезет в чужую логику напрямую
- Без дублирования: общая логика выносится в shared/, не копируется между модулями

- Простота: код читается как текст — без магии, без хитростей
- Одна функция — одна задача, не больше 20–40 строк

## Архитектура памяти проекта

Система файлов памяти — кто что пишет, кто только читает.

| Файл / Папка | Назначение | Пишет | Остальные |
|-------------|-----------|-------|-----------|
| `CURRENT_TASK.md` | Текущая задача, статус, контекст | Дима | Читают |
| `PROJECT_CONTEXT.md` | Стек, архитектура, факты о проекте | Дима | Читают |
| `REQUIREMENTS.md` | Требования: v1 / v2 / вне скопа | Дима | Читают |
| `ROADMAP.md` | Фазы и задачи со статусами и волнами | Дима | Читают |
| `DECISIONS.md` | Почему выбрали подход А, а не Б. Forensics неудач. | Дима | Читают |
| `BACKLOG.md` | Идеи на будущее с триггерами | Дима | Читают |
| `threads/*.md` | Персистентные нити контекста по темам | Дима | Читают |
| `CHANGE_HISTORY.md` | Что менялось в коде | Артём | Читают |
| `tz/*.md` | Исходные ТЗ от пользователя — первоисточник | Пользователь | Читают |
| Файл агента | Опыт и знания конкретного агента | Сам агент | Не читают |

**Принцип:** один файл = один писатель. Ноль конфликтов при параллельной работе.

**Архивация:** завершённые фазы ROADMAP → `archive/phase-N.md`. Закрытые threads → `archive/threads/`.
